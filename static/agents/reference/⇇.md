# ⇇

Exact-output transfer: sink ⇇ payload invokes a callable sink value once per payload — no formatting, no separators, no channel selection, no conversions.

**Term** `⇇` · **Section** OPERATORS · **Also** `transfer`

## Syntax

```
<sink> ⇇ <payload> (⇇ <payload>)*
```

## What this teaches

- Callable sink — `sink ⇇ payload` invokes a callable sink value (one argument, `void` result) once per payload; the bound value owns destination and behavior, and the compiler holds no console knowledge
- No formatting — the operator adds no separator or terminator, selects no channel, and runs no conversions; formatting is explicit on the right, e.g. `output ⇇ "§ §\n"(a, b)`
- Chain — `sink ⇇ a ⇇ b` evaluates the sink expression once, each payload once left-to-right, and invokes the sink once per payload left-to-right; the chain result is `void`
- Precedence — `⇇` binds below assignment and above ternary: postfix calls, conversions, and string-constructor applications finish before transfer (EBNF [126] `transfer ::= ternary ('⇇' ternary)*`, consumed by [127] `assignment ::= transfer ('←' assignment | '↤' assignment …)?`)
- Sinks arrive as values — the sink may be an imported callable (see selective_import) or any callable local, parameter, or member value

## Common mistakes

- expecting `⇇` to print — the compiler formats nothing; import a sink value (e.g. `import from "norma:console" const dic as output`) and format explicitly on the right
- using the chain result — a transfer chain is `void`, never a payload

## Example

```fab
fn mittite((string) → void sink, string name) → void {
    sink ⇇ name
}

fn mittite_duplex((string) → void sink, string prior, string posterior) → void {
    sink ⇇ prior ⇇ posterior
}

main {
    const string name ← "salve"
    print name
}
```
